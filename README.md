# Turon Tour — кабинет агентства (B2B)

Инструмент для агентств-партнёров: агентство входит под своим логином,
видит заезды со свободными местами и ценами, бронирует пассажиров и
следит за оплатой.

## Возможности

Публичный каталог — виден **без входа**, чтобы агент показывал тур клиенту
по ссылке:

- Направления → туры → карточка тура с постоянным адресом
  (`#/t/KARADENIZ`), который можно отправить в мессенджере
- Карточка тура: программа по дням, что включено и что нет, важные
  оговорки, заезды с ценами и остатком мест
- У тура может быть несколько вариантов маршрута с переключателем — у
  Карадениза их два, зеркальных, с разным направлением перелёта
- Партнёрские цены гость видит, комиссии — нет; бронь только после входа

Кабинет агентства:

- Вход агентства по логину и паролю
- Список заездов: дата, аэропорт прилёта (Трабзон / Батуми), свободные
  места, цены по размещению и детские тарифы
- Бронирование: пассажиры с ФИО, датой рождения, паспортом и типом
  размещения; цена считается автоматически по возрасту на дату выезда
- Место занимается сразу при бронировании — заезд нельзя перепродать
- Предупреждение, если паспорт истекает до поездки или раньше чем через
  6 месяцев после неё
- Младенцы (до 2 лет) не занимают место в квоте
- Свои брони с суммой, оплатой и остатком; отмена возвращает места
- Правка состава брони без пересоздания — номер брони сохраняется
- Комиссия агентства: за каждого проданного туриста, сводка заработка
- Каталог туров с размером комиссии по каждому направлению

Для сотрудника туроператора (роль `operator`):

- Список пассажиров любого заезда и **выгрузка в CSV** в колонках исходной
  ведомости — открывается в Excel как привычная таблица
- Сводка по заезду: броней, пассажиров, продано, оплачено, долг
- Все брони по всем агентствам с отбором по агентству, заезду, статусу
  и долгу, поиском по номеру брони и фамилии; внесение оплат и возвратов
- История по каждой брони: кто создал, менял, отменял и вносил оплату
- Заведение агентств, отключение и смена пароля

## Как это работает

Единица работы — **заезд** (дата + транспорт), а не «тур»: агентство
сажает пассажиров в конкретный рейс.

**Цена пассажира** определяется автоматически: если возраст на дату
выезда попадает в детский тариф — берётся он, иначе взрослая цена по
типу размещения. Возрастные границы трактуются как «от и до, не
включая верхнюю»: тариф `Chd 5-10` применяется с 5 лет до 10.

**Комиссия** задаётся на туре в долларах за проданного туриста и
фиксируется в брони на момент продажи: изменение тарифа не переписывает
задним числом уже заработанное. Младенцы места не занимают и продажей не
считаются. Комиссия оператора идёт сверху агентской и агентству не
показывается.

В продаже только **предстоящие** заезды: место в уже улетевшем рейсе
продать нельзя. Оператору прошедшие заезды видны — по ним он выгружает
списки пассажиров.

**Места** списываются одним UPDATE с проверкой лимита прямо в условии.
Если два агентства бронируют последние места одновременно, второй запрос
не пройдёт и вернёт ошибку — вместо продажи одного места дважды.

## Запуск локально

Фронтенд — чистая статика, сборка не нужна:

```bash
python3 -m http.server 8000
# затем откройте http://localhost:8000
```

Без настроенного бэкенда кабинет работает в **демо-режиме**: реальные
заезды и цены, но брони хранятся в браузере. Демо-логины: `umida`,
`easytourism`, `ofotour`, оператор — `operator`, пароль у всех `turon2026`.
Это пароли только браузерного демо; учётки в базе создаются со своими,
случайными.

## Проверка бэкенда

Перед деплоем — прогон воркера и базы по-настоящему, на локальной D1:
см. [test/README.md](test/README.md).

## Развёртывание бэкенда

```bash
cd worker
wrangler d1 create turon-tour          # id из вывода вписать в wrangler.toml
wrangler d1 execute turon-tour --remote --file=../db/schema.sql
wrangler d1 execute turon-tour --remote --file=../db/seed.sql
wrangler deploy
```

Затем в `js/config.js` указать адрес воркера:

```js
window.TURON_CONFIG = { apiBaseUrl: "https://turon-tour-api.<субдомен>.workers.dev" };
```

Пароли генерируются случайными при сборке `db/seed.sql` и печатаются в
консоль **один раз** — сохраните их сразу. В самом SQL лежат только хеши.

После деплоя укажите адрес кабинета в `ALLOWED_ORIGIN` (`worker/wrangler.toml`),
иначе к API сможет обращаться любая сторонняя страница.

## Структура

```
index.html            каталог, вход и кабинет (одна страница)
styles.css            оформление, светлая и тёмная темы
js/config.js          адрес бэкенда; пусто — демо-режим
js/seed-data.js       заезды, туры, направления (сгенерировано, не править руками)
js/api.js             клиент API + демо-режим на localStorage
js/catalog.js         публичный каталог и карточка тура
js/app.js             экраны кабинета
db/schema.sql         схема базы
db/seed.sql           наполнение (сгенерировано)
db/migrations/        ALTER-ы для баз, созданных прежней схемой
worker/index.js       API на Cloudflare Workers + D1
tools/                извлечение данных из ведомости и сборка превью
seed/departures.json  выгрузка заездов и цен из ведомости
preview.html          однофайловое превью (сгенерировано)
```

Файлы с пометкой «сгенерировано» пересобираются командами:

```bash
python3 tools/extract-departures.py ведомость.xlsx > seed/departures.json
python3 tools/build-seed.py > db/seed.sql
node tools/build-preview.js
```

## О данных

Заезды, вместимость и цены взяты из рабочей ведомости броней за 2026 год.
**Персональные данные пассажиров в репозиторий не переносились**: от уже
проданных мест взято только их количество, чтобы остаток мест по каждому
заезду соответствовал действительности.

Известные расхождения в исходной ведомости, которые стоит выверить:

- граница детского тарифа менялась по ходу сезона: до 10.07 — `Chd 5-11`,
  с 17.07 — `Chd 5-10`;
- у заездов одной даты детские цены иногда различаются (05.06: Батуми
  630, Трабзон 600);
- цена одноместного размещения задана не у всех заездов;
- у инфотура 22.05 детских тарифов нет вовсе, а трёхместное размещение
  дороже двухместного;
- вместимость заезда в ведомости не указана — принято 65 мест
  (максимальная фактическая загрузка — 64), уточнить и поправить
  в `tools/build-seed.py`.

Японские туры заведены как продукты с комиссиями (100/150/250/250), но
закрыты для брони: по ним нет ни дат заездов, ни цен. Открыть — проставить
даты и прайс и снять `is_bookable = 0` в `tools/build-seed.py`.
